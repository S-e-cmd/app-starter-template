# Template Validation Checklist

新規アプリ作成時、継続改修時、既存アプリ非破壊整備時に、GitHub Actionsへ依存せずその場で確認するためのチェックリストです。

## ブートストラップ完了ゲート

新規アプリでは、アプリ固有機能の実装完了より先に `docs/BOOTSTRAP_PROTOCOL.md` を満たしてください。

次のすべてが揃うまで初期実装完了扱いにしません。

- `ai-context.json` がアプリ直下にある。
- `llms.txt` がアプリ直下にある。
- `docs/ARCHITECTURE.md` がある。
- `docs/DATA_CONTRACT.md` がある。
- `docs/UI_RULES.md` がある。
- `docs/PROJECT_STATUS.md` がある。
- `ai-context.json` から親テンプレートの公開 `manifest.json` へ戻れる。
- `core` が適用されている。
- 要件に応じた追加構成だけが適用されている。
- 責務分割済みの基盤がある。

READMEやアプリ固有コードだけが存在しても、上記が欠けていれば未ブートストラップです。

## 新規アプリ作成時

- ユーザーへ `Use this template` を要求していない。
- ユーザーへ CORE / Worker / D1 / Sheets-GAS の選択を要求していない。
- AIが要件から構成を判断した。
- `index.html` から `/ai-context.json` を発見できる。
- ビルド番号が `YYYYMMDD-NN` 形式で画面と設定に反映されている。
- UI、通信、保存、状態管理、業務処理が責務別に分離されている。
- GitHub Actionsが理由なく追加されていない。

## 既存アプリ非破壊整備時

`docs/EXISTING_APP_ALIGNMENT_PROTOCOL.md` を優先し、次を確認します。

- テンプレート準拠を目的にしていない。
- 既存構成をテンプレートのディレクトリ構成へ変換していない。
- テンプレートとの差分だけを理由に変更していない。
- 公開ページの実挙動とリポジトリの現在状態を変更前に確認した。
- 既存機能、主要UIフロー、データ契約、API、公開方式を保護対象として扱った。
- LocalStorageキー、D1 schema、Sheets列、JSON形式、既存ID、Binding、Secret / Variable名、公開URLを不用意に変更していない。
- 1バッチで扱う範囲を限定した。
- `確認 → 修正 → 回帰確認 → 記録` を同じバッチ内で完結させた。
- 不具合修正と大規模リファクタリングを同じバッチに混在させていない。
- 権限やツール上の制約がある場合も、可能な確認・修正・代替作業を進めた。
- ユーザー操作が必要な箇所だけ具体的な手順として残した。
- 未確認事項と確認済み異常を区別した。
- 不足していた引き継ぎ資料を現在の実態に合わせて追加・更新した。
- `PROJECT_STATUS.md` に変更範囲、確認済み範囲、未確認範囲、残タスク、意図的な例外を記録した。

既存アプリの完了条件はテンプレートとの一致ではありません。既存動作とデータ互換性を維持しながら、安全に継続作業できる状態になっていることを確認します。

## 機能追加・修正時

`docs/FEATURE_CHANGE_PROTOCOL.md` を使用し、次を確認します。

- 変更対象と関連ファイルを先に確認した。
- 呼び出し元・呼び出し先・共有状態を確認した。
- 既存の類似機能・共通部品・再利用候補を確認した。
- 保存先、API、外部サービス、公開方式への影響を確認した。
- 新しい責務を既存巨大ファイルへ安易に追記していない。
- 必要な責務分離は今回の変更に直接関係する小さな境界に限定した。
- 無関係な大規模リファクタリングを混在させていない。
- APIや保存形式の互換性を確認した。
- LocalStorageキー、D1 schema、Sheets列、既存ID、Binding、Secret / Variable名を理由なく変更していない。
- 待ち時間のある操作に処理中表示と二重操作防止がある。
- PC/SP双方への影響を確認した。
- 構文・通信・保存・初期表示・再読み込みを確認した。
- 追加機能に隣接する既存操作を回帰確認した。
- 構成変更時に `ARCHITECTURE.md` を更新した。
- データ契約変更時に `DATA_CONTRACT.md` を更新した。
- UI制約変更時に `UI_RULES.md` を更新した。
- 状態変更時に `PROJECT_STATUS.md` を更新した。
- エントリーポイントや主要構成変更時に `ai-context.json` を更新した。
- ビルド番号を更新した。
- 公開を伴う場合は公開画面とリポジトリのビルド番号一致を確認した。

## 引き継ぎ確認

次のどちらからでも現在状態と共通ルールへ辿れることを確認する。

1. 公開アプリURL → `/ai-context.json` / `/llms.txt` → ローカルdocs → 親manifest
2. GitHubリポジトリ → `ai-context.json` / README → ローカルdocs → 親manifest

コードだけが更新され、引き継ぎ情報が古い状態は完了扱いにしない。
