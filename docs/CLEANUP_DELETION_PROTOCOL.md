# Cleanup and Deletion Protocol

不要コード、不要ファイル、古い設定、旧API、古いUI等を整理・削除する場合の安全手順です。

## 基本原則

- 「使っていなさそう」を削除理由にしない。
- 削除は整備の最後に行う。
- 参照元・動的参照・外部連携・互換処理を確認してから削除する。
- 大量削除、一括rename、大規模移動を同じバッチで行わない。
- 削除前後で機能差分を確認する。

## 削除前確認

1. 静的参照を確認する。
2. HTML、Worker、GAS、設定、JSON、manifest等からの参照を確認する。
3. 動的import、文字列参照、イベント名、API route、外部URL経由の利用を確認する。
4. 古いデータ読み込みやmigrationのために残っていないか確認する。
5. 公開環境でまだ必要な資産でないか確認する。

## 実施

- 1バッチの削除範囲を限定する。
- renameと削除を同時に大量実施しない。
- まず参照を外し、回帰確認後に削除する方法を優先する。
- 互換コードは移行完了確認前に削除しない。

## 確認

- 初期表示。
- 対象機能と隣接機能。
- 保存・再読み込み。
- API/route。
- PC/SP表示。
- 公開環境。

## 禁止事項

- 行数削減だけを目的とした削除。
- 未確認ファイルを一括で消す。
- 動的参照を確認せず削除する。
- 削除と大規模リファクタリングを同じバッチに混在させる。

## 記録

削除理由、確認した参照、削除したもの、残した互換処理、回帰確認結果を `docs/PROJECT_STATUS.md` に記録します。
