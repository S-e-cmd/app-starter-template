# UI Rules

- 明示的な依頼がない限り、既存画面構成・主要導線・情報量を変更しない。
- 新機能追加のために既存要素を縮小・削除しない。
- PC/SPの双方で操作可能な状態を維持する。
- ボタン、入力欄、モーダル、トースト、処理中表示は既存共通実装を優先する。
- 一覧性を目的とする画面では、詳細機能追加によって一覧性を落とさない。
- 待ち時間のある操作は処理内容を表示し、二重操作を防止する。
- 成功、失敗、未実行、再試行待ちを区別する。
- 新しい色・カード・モーダルなどを理由なく追加しない。
- UI上の維持事項や例外が増えた場合は、各アプリの `docs/UI_RULES.md` に記録する。
