# Batch Completion Choices

既存アプリ非破壊整備モードでは、選択肢提示が必要な場合だけこの形式を使用します。

ユーザーが現在の依頼で「完了まで進める」「ロードマップ通り継続」「残課題を順に処理」等を既に明示している場合、当初scope内の安全な次バッチへ進むために毎回この選択を要求しません。

## 選択肢提示が必要な条件

- 当初scopeを超える。
- 新たなProduction Mutation・破壊的操作の個別authorizationが必要。
- 高リスクProtocolへの切替でユーザー判断が必要。
- 複数の実質的に異なる方針から選択が必要。
- ユーザーが各バッチで選択肢提示を希望している。
- 整備必要度が低く、当初の継続指示の対象も概ね完了している。

## 表示ルール

推奨する選択肢には `← 推奨` を付けます。

例:

```text
[今回は終了] ← 推奨 — 現在の整備必要度が低く、当初範囲の残りは任意改善中心
[続ける] — app.js 内部の保存処理だけを限定的に整理
[別の箇所を優先] — 気になる機能・UI・保存・公開周りなどを指定
```

## 選択肢の意味

### 今回は終了

現在状態、verified / blocked範囲、残タスク、次回再開位置を `docs/PROJECT_STATUS.md` に残して終了します。

### 続ける

AIが `docs/PROJECT_STATUS.md`、現在scope、整備必要度から次の安全なバッチを1つ選びます。表示時には何を次に行う予定かを短く具体的に添えます。

### 別の箇所を優先

現在の自動候補ではなく、ユーザーが指定した箇所を次バッチ対象に切り替えます。表示時には `気になる機能・UI・保存・公開周りなどを指定` のように、何を指定すればよいか分かる説明を添えます。

ユーザーが対象を指定せずこの選択肢だけを選んだ場合は、対象箇所だけを確認します。勝手に別の整備対象を選びません。

## 禁止

- 既に継続許可があるのに、機械的に毎バッチ停止する。
- `[続ける]` などlabelだけを並べ、何が起きるか説明しない。
- 推奨理由を示さずに選択を求める。
- `別の箇所を優先` をAI側の別候補選択として扱う。
- 整備必要度が低いのに、継続を既定として誘導する。
