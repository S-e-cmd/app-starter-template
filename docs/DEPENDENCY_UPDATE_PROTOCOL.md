# Dependency Update Protocol

ライブラリ、SDK、ランタイム、ビルド基盤等の依存更新を通常の機能追加から分離して安全に扱うための手順です。

## 基本原則

- 機能追加のついでに依存更新しない。
- major updateは独立バッチで扱う。
- 「新しいから」という理由だけで置き換えない。
- API変更、ブラウザ互換、Cloudflare/GAS/Node等の実行環境互換を確認する。
- 正常稼働している既存依存を、テンプレート既定へ合わせるだけの目的で置換しない。

## 変更前確認

1. 現在バージョンと利用箇所を確認する。
2. 更新理由を明確にする。
3. breaking changes、deprecated API、設定変更を確認する。
4. ロックファイル、ビルド設定、ランタイムへの影響を確認する。
5. 元バージョンへ戻せる状態を確保する。

## 実施

- 一度に複数の大きな依存を更新しない。
- 依存更新と大規模リファクタリングを分ける。
- 必要な設定変更だけ行う。
- 既存APIを置き換える場合は影響範囲を限定する。

## 確認

- インストール/ビルド。
- 初期表示。
- 主要機能。
- API通信。
- 保存・再読み込み。
- PC/SP表示。
- 公開環境。

## 禁止事項

- 更新理由のない一括アップデート。
- major updateと機能追加の同時実施。
- 互換確認なしのランタイム変更。
- 公開確認なしで完了扱いにする。

## 記録

更新理由、旧/新バージョン、必要なコード変更、確認結果、戻し方を `docs/PROJECT_STATUS.md` に記録します。
